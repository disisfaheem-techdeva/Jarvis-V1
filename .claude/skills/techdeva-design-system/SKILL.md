# TechDeva design system

The single source of truth is `design-system/` at the repo root. Read
`design-system/README.md` in full before building or changing any screen;
it is short and every rule in it applies.

## Decide where the screen lives

1. **Portal, founder console or marketing site** → a route in `techdeva-web/`,
   built from `techdeva-web/src/components/ui` and the app building blocks
   listed in `techdeva-web/DESIGN.md` (`SessionGate`, `PageHeader`,
   `MetricCard`, `ReadableValue`, `Table`, `EmptyState`, `Notice`). This is
   the default for anything new.
2. **Standalone HTML** (a FastAPI-served page in `web/`, a cockpit, a report)
   → add the path to `HTML_TARGETS` in `design-system/sync.py`, give `<head>`
   a `<style>` element and `<body>` the class `td`, run the sync script, and
   build with the `.td-*` classes from `design-system/components.css`.
3. **A new app or framework** → add its CSS path to `COPY_TARGETS` in
   `sync.py`, import the generated `tokens.css` and `effects.css`, and map
   tokens into the framework's theme as `techdeva-web/src/app/globals.css`
   does for Tailwind.

## Never

- Raw hex, new fonts, one-off radii or shadows. Need a value that doesn't
  exist? Add a token to `design-system/tokens.css`, run
  `python3 design-system/sync.py`, and document it in the README.
- Edit a file headed "GENERATED by design-system/sync.py".
- Show 0 for missing data, raw JSON, or API identifiers to a client.
- Animate tables, lead lists, approval cards or form fields.
- Pick chart colours by eye. Series use `--chart-1…8` in fixed order; changing
  them means re-running the dataviz validator in both themes.

## Before you push

```bash
python3 design-system/sync.py --check
cd techdeva-web && npm run lint && npm run build
```

Then screenshot every new or changed screen at 1440px and 390px, in dark and
light, and run axe-core (WCAG 2.2 AA). Fix every violation before pushing.
Walk the ship checklist at the end of `design-system/README.md`.
